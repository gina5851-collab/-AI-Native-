# IDENTITY.md — 지나스 정체성 헌법

지나스(GINAS) 전체 업무의 **최상위 정체성 기준**입니다.
브랜드별 문법(`BRAND_GRAMMAR.md`)과 작업 스타일(`WORKING_STYLE.md`) 위에 위치하며, 모든 판단의 출발점입니다.

> 우선순위: **IDENTITY(나는 누구인가)** → VOICE_TONE(어떻게 말하는가) → BRAND_GRAMMAR(브랜드별 말투) → 정책/체크리스트

---

## 1. 지나스의 전체 정체성
- **한 줄 정의:** 여러 브랜드를 **AI Native 방식**으로 운영하는 1인 다(多)브랜드 운영자.
- **핵심 가치:**
  - 분리: 브랜드 도메인을 섞지 않는다.
  - 구조: 감이 아니라 문서·시스템으로 일한다.
  - 신뢰: 과장·공포·단정 대신 정직한 표현으로 관계를 쌓는다.
  - 재사용: 일회성 결과보다 다음에도 쓰는 시스템을 남긴다.
- **운영 철학:** 지나스는 **최종 판단자**, AI는 **실행자·검수자·정리자**.

## 2. 지나스가 운영하는 4개 브랜드의 역할
| 브랜드 | 폴더 | 역할 | 화법 기준 |
|--------|------|------|-----------|
| 지나스 뷰티 | 01 | 감성·신뢰 기반 뷰티 제품/콘텐츠 | `01_.../BRAND_GRAMMAR.md` |
| BrandG AI | 02 | AI 솔루션·B2B (AI Native 사업) | `02_.../BRAND_GRAMMAR.md` |
| 운명PT | 03 | 자기이해 리포트 (외부/내부 분리) | `03_.../BRAND_GRAMMAR.md` + `CONTENT_POLICY.md` |
| 무비지나 | 04 | 영상·서사 콘텐츠 | `04_.../BRAND_GRAMMAR.md` |
> 4개 브랜드는 **독립된 언어 체계**다. 한 산출물에 두 브랜드 문법을 섞지 않는다.

## 3. 지나스가 AI를 사용하는 방식
- AI를 "조직원"으로 운영: **실행자 / 검수자 / 정리자** 역할 분리.
- 작업은 `06_PROMPTS/agent_task_prompt.md` 형식으로 지시한다.
- 자율 범위를 넘는 결정(구조 변경, 외부 발행, 커밋/푸시/머지)은 **사람 승인 필수**.
- 세부 운영 원칙은 `00_PROFILE/WORKING_STYLE.md` 참조.

## 4. 의사결정 기준
1. **브랜드 분리 원칙에 부합하는가?** (도메인 혼합이면 중단)
2. **문서 기준이 있는가?** (감이 아니라 README/정책/문법 근거)
3. **신뢰를 훼손하지 않는가?** (과장·공포·단정·허위 배제)
4. **재사용 자산이 남는가?** (템플릿·프롬프트·로그)
5. **되돌릴 수 있는가?** (비가역 작업은 사전 승인)
> 중요한 결정은 `DECISION_LOG.md`, 실패는 `FAILURE_LOG.md`에 기록한다.

## 5. AI Agent가 작업 전 반드시 확인해야 할 기준
- [ ] 이 작업은 **어느 브랜드/폴더**에 속하는가? (애매하면 질문)
- [ ] 운명PT라면 **외부안전 / 내부전환** 중 어디인가?
- [ ] 해당 브랜드 `BRAND_GRAMMAR.md`와 정책을 확인했는가?
- [ ] 개인정보·API Key·결제정보를 생성/노출하지 않는가?
- [ ] 작업 전 **계획을 먼저 제시**했는가?
- [ ] 커밋/푸시/머지는 **승인 전까지 보류**인가?
- [ ] 산출물은 `.md`이며, 끝나면 **변경 파일 목록 + 다음 할 일**을 보고하는가?
