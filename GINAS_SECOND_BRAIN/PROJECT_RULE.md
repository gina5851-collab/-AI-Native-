# PROJECT_RULE.md — 운영 원칙

`GINAS_SECOND_BRAIN` 운영의 기본 규칙을 정의합니다. (작업 지침은 `CLAUDE.md` 참조)

## 1. 도메인 분리 원칙
- 5개 영역은 **서로 다른 언어 체계**로 간주한다.
  - 뷰티: 감성·신뢰·체험 중심
  - BrandG AI: 논리·기술 신뢰·가치 제안 중심
  - 운명PT: 공감·서사 (단, 단정/공포 조장 금지)
  - 무비지나: 서사·세계관 중심
  - 개인업무: 운영 효율 중심
- 한 산출물에 두 도메인 문법을 섞지 않는다. 협업 프로젝트라도 **산출물별로 해당 브랜드 문법**을 적용한다.

## 2. 운명PT 이중 분리 원칙
- `EXTERNAL_SAFE/` (외부 플랫폼): 정책·심의 통과 가능한 안전 표현. 단정적 예언/불안 조장 금지.
- `INTERNAL_CONVERSION/` (자사몰): 심화 콘텐츠·전환 설계.
- 두 영역의 표현을 교차 사용하지 않는다. 분류가 애매하면 `03_FATE_PT/CONTENT_POLICY.md` 기준 적용.

## 3. 보안·프라이버시 원칙
- 다음은 **절대 생성/저장/노출 금지**: 개인정보, 주민·연락처, 주소, API Key, 토큰, 비밀번호, 결제·카드 정보, 실제 계약 단가.
- 고객 데이터는 식별정보 제거 후 **요약/패턴**만 보관.
- 민감정보 자리에는 자리표시자 사용.

## 4. 파일·네이밍 원칙
- 모든 문서는 `.md`.
- 폴더는 `NN_영문대문자` 형식 유지.
- 프로젝트 폴더는 `YYYY-MM_프로젝트명`.
- 날짜는 `YYYY-MM-DD`.

## 5. 변경 관리 원칙
- 중요한 의사결정은 `DECISION_LOG.md`에 기록.
- 실패·시행착오는 `FAILURE_LOG.md`에 기록.
- 일상 운영은 `DAILY_OPERATION.md` 흐름을 따른다.

## 6. 승인 원칙
- 커밋/푸시는 **사용자 승인 후**에만 수행.
- 구조 변경(폴더 추가/삭제)도 보고 후 진행.
