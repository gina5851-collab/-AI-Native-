# harness/

**규칙·정책·검수 기준 저장소**

G-Wiki의 운영 규칙, 보안 정책, 공개 콘텐츠 검수 기준을 보관한다.

## Public Content Review

공개용 콘텐츠 생성 전 반드시 검수한다.

검수 항목:

- 개인정보
- 고객정보
- API 키
- 환경변수
- 관리자 화면
- DB 구조
- 결제 구조
- 프롬프트 원본
- 내부 프로젝트명
- 저작권
- 상표권
- 초상권
- 플랫폼 정책

## Forbidden

절대 하지 말 것:

원본 삭제 · 무단 커밋 · 무단 push · main merge · 배포 · DB 변경 ·
환경변수 변경 · 고객정보 저장 · API 노출 · 프롬프트 공개

## Sensitivity 분류

| 등급 | 설명 |
| --- | --- |
| public | 공개 가능 |
| internal | 내부 전용 |
| confidential | 민감정보 (개인정보·고객정보·키·결제) |

## 고객정보 충돌 해소 규칙

Core Rule의 **"원본 절대 삭제·보존"** 과 Forbidden의 **"고객정보 저장 금지"** 는
고객 개인정보가 포함된 원본이 유입될 때 충돌한다. 이 충돌은 아래 규칙으로 해소한다.

**원칙: 고객 개인정보 원본은 G-Wiki에 저장하지 않는다. ("보존 금지"가 "보존 의무"보다 우선한다.)**

판정 대상 (= 고객 PII로 간주):

- 이름·연락처(전화·이메일)·주소
- 주민등록번호·생년월일 등 식별번호
- 결제·카드·계좌 정보
- 로그인·인증 정보, API 키, 환경변수
- 고객이 제출한 사진·음성 등 초상/생체 정보

처리 절차 (Ingest 1단계에서 적용):

1. **분리(quarantine)** — 고객 PII가 포함된 원본은 `sources/`에 그대로 저장하지 않는다.
2. **비식별 정제** — 자산화 가치가 있는 부분만 PII를 제거/마스킹한 **정제본**으로 변환한다.
   - 마스킹 예: 이름→`고객A`, 전화→`010-****-****`, 이메일→`***@***`
3. **저장** — 비식별 정제본만 `distillations/`에 `sensitivity: confidential`로 저장한다.
4. **원본 처리** — PII 원본은 G-Wiki 밖(고객정보 보관은 별도 시스템/대장)에서 관리하며,
   G-Wiki에는 "원본은 외부 보관됨"이라는 **포인터(메타)만** 남긴다. 실제 PII 값은 남기지 않는다.

요약: **"원본 보존"은 G-Wiki 자산에 한정한다. 고객 PII는 처음부터 G-Wiki 자산이 아니다.**
따라서 PII를 저장하지 않는 것은 원본 삭제가 아니라 *애초에 수집 대상에서 제외*하는 것이다.
